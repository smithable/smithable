# Releasing to npm

The engine is published as `smithable` (the CLI), `create-smithable` (`npm create smithable`) and the packages under `@smithable/` (`core`, `adapter-tanstack`, `index`, `ai`). Nothing is published until a release is run by hand.

- **How:** Actions → Publish → Run workflow, with the version (like `0.1.0`). The box "dry run" is ticked by default: the packages are built, tested and packed, and nothing is uploaded. Untick it to publish. If the web button fails with "Workflow dispatch failed" (it did once, for 0.1.0), start it from the command line: `gh workflow run publish.yml --ref main -f version=0.1.0 -f dry_run=false`.
- **Prereleases:** a version with a prerelease part (`0.2.0-rc.1`) is published under the npm tag `next`, so `npm install smithable` keeps getting the release under `latest`; `npm install smithable@next` gets the prerelease. Any other version goes to `latest`.
- **Approving:** the workflow only stages each version (trusted publishing in stage-only mode, no token); the release account approves them on npmjs.com with its passkey, or from the command line. For that, sign in to the release account in its own config file, `npm login --userconfig ~/.npmrc-ops`, and pass `--userconfig ~/.npmrc-ops` to every npm command of the release (`npm stage approve <id> --userconfig ~/.npmrc-ops`, `npm deprecate … --userconfig ~/.npmrc-ops`), so your own npm sign-in is never used for it.
- **What happens:** `scripts/set-version.mjs` stamps the version into every package and the CLI's `VERSION` (not committed: the repository stays at 0.0.0, which generated apps record until the first release), then build, units, and `npm stage publish` for every package; npm adds provenance itself. Before packing, `scripts/prepack.mjs` copies LICENSE and NOTICE into each package and the built Studio app into the CLI (`studio/`, which it serves when installed).
- **Licences:** Apache-2.0 for the engine; `@smithable/adapter-tanstack` is `Apache-2.0 AND 0BSD`, its app kit and templates being 0BSD (KIT-LICENSE).
- **Needs:** nothing stored: npm trusts the workflow as a publisher of `smithable`, `create-smithable` and the `@smithable` packages (OIDC, `id-token: write`), all owned by the release account, not a personal one.
- **Placeholders:** deprecated at 0.1.0 (0.0.3 of `smithable` and `create-smithable`, 0.0.0-stage and 0.0.1 of the four `@smithable` packages). Never unpublish every version of a package: that frees the name.
- **Each release:** a section in [CHANGELOG.md](../CHANGELOG.md), with what breaks under **Breaking** ([CONTRIBUTING.md](../.github/CONTRIBUTING.md#compatibility)).
