# Working on this app

This app is generated by [Smithable](https://smithable.ai) from `smithable.yml` (what it does), `smithable.auth.yml` (sign-in, roles, access) and `smithable.content.yml` (visible text). The code follows the usual TanStack Start, Drizzle and shadcn/ui idioms, but most of it is regenerated on every change.

## Change the app through Smithable, not by editing files

- **With MCP** (`.mcp.json` registers `smithable mcp`): call `smithable_context` with the request to see the parts of the app it is about, then an operation tool such as `smithable_add_field`. Each operation checks the change, regenerates the code, migrates the database and commits a checkpoint; `smithable_undo` reverts it. `smithable_inspect` shows any concept with its files and tests.
- **Without MCP:** `smithable context "<request>"`, `smithable op <operation> …` (`smithable op` lists them), `smithable inspect <concept>`, `smithable undo`.
- You rarely need to read the source to make a change.

## Who owns which files

| Path | Owner | |
|---|---|---|
| `smithable*.yml` | The project | Changed through operations |
| `src/generated/`, `src/db/schema.ts`, `src/db/seed.ts`, generated routes, `src/lib/auth.ts` | Smithable | Overwritten on every change: never edit |
| `src/kit/`, `src/components/ui/` | Smithable | Updated with Smithable: never edit; copy into `src/custom/` to change |
| `src/custom/` | You | Never touched by Smithable |
| `drizzle/` | History | Migrations; never edit old ones |

## Custom code

- A custom action's implementation is `src/custom/actions/<action>.ts`. Its input and output types come from the spec.
- Read and write data with the functions in `src/generated/<model>.server.ts`: they apply the access rules. The signed-in user is `await currentViewer()` from `#/lib/viewer.server`.
- Mark code that implements a rule with `// implements rule <id>`, and its test with `test("rule <id>: …")`, then run `smithable test`: `smithable inspect` shows each rule's status.
